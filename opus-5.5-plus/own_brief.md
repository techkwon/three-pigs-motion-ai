# 설계서: 「문 열어, 나야 — 아기 돼지 삼형제, 오늘의 이야기」

- 산출물: 현재 작업 폴더의 `index.html` 하나(인라인 SVG + CSS + JS, 외부 자원 0개, 소리 없음)
- 길이: **89.0초** (재생 조건 「약 60~90초」 안)
- 화면: 16:9 기준 SVG `viewBox="0 0 1600 900"`
- 이 설계서는 2단계 구현의 기준이다. 구현 중 바꾸면 이 문서의 해당 줄을 같이 고친다.

---

## 0. 한 줄 요약

> 늑대는 이제 문을 부수지 않는다. **아는 사람인 척 문을 두드린다.**
> 비밀번호 「1234」 집은 한숨에 열리고, AI 목소리에 속는 「똑똑한 문」도 열리지만,
> 「우리만 아는 질문」으로 한 번 더 확인한 셋째의 벽돌 집은 열리지 않는다.
> 그리고 셋째는 문을 닫고 혼자 안전해지는 대신, 그 습관을 이웃과 나눈다.

## 1. 주제와 메시지

### 1-1. 고른 현대적 주제
**디지털 시대의 「집」 = 계정(개인 정보와 디지털 생활 공간), 늑대 = 사칭·피싱(AI 목소리 흉내 포함)**

- 참고 작품 두 편이 모두 「폭염·기후」를 골랐다. 같은 주제를 피해서 새로움(스토리 구성 점수)을 얻는다.
- 중학생에게 직접 닿는 주제다. 「엄마 폰 고장 났어」식 문자, 택배·당첨 문자, AI 목소리 흉내는 학생과 가족이 실제로 겪는 일이다.
- 원작의 늑대 대사 「아기 돼지야, 문 열어 줘」와 사칭(「문 열어, 나야」)이 그대로 겹쳐서, 원작의 뼈대가 억지 없이 살아난다.

### 1-2. 전하려는 메시지
**가장 튼튼한 벽돌은 「한 번 더 확인하는 습관」이고, 가장 튼튼한 동네는 그 습관을 나누는 이웃이다.**
- 보조 메시지 1: 편하기만 한 문(쉬운 비밀번호)도, 기술에만 맡긴 문(목소리 인식·자동 로그인)도 흉내에는 약하다.
- 보조 메시지 2: 급하다고 할수록 멈추고 확인한다(우리만 아는 질문, 링크 누르지 않기, 신고·차단).

### 1-3. 원작 대응표 (뼈대 유지, 의미 새로 쓰기)

| 원작 | 이 작품 | 의미 |
|---|---|---|
| 세 형제가 독립 | 세 형제가 처음 자기 휴대폰·계정을 가짐 | 「계정이라는 두 번째 집」 |
| 첫째 · 짚 집 | **포스트잇 집** — 모든 문 비밀번호 「1234」 | 편함 = 쉽게 뚫림 |
| 둘째 · 나무 집 | **스마트 패널 집** — 목소리로 열리는 문 + 자동 로그인 | 기술만 믿음 = 흉내에 속음 |
| 셋째 · 벽돌 집 | **벽돌 집** — 벽돌마다 습관(문마다 다른 비밀번호, 두 단계 로그인, 한 번 더 확인, 우리만 아는 질문) | 느리지만 단단한 습관 |
| 늑대가 후~ 불어 집을 날림 | 늑대가 「1234」를 눌러 열고, 후~ 불어 포스트잇을 날림 / AI 목소리로 문을 열고 패널을 떨어뜨림 | 공격은 「흉내」 |
| 「문 열어 줘」 「싫어!」 | 엄마 목소리 흉내 → 셋째가 「우리 집 질문」을 물음 → 늑대가 답을 못 함 | 확인 질문 |
| 늑대가 숨을 불어도 벽돌 집은 끄떡없음 | 가짜 문자 폭풍이 벽돌 벽에 튕겨 나감 | 습관의 벽 |
| 늑대가 굴뚝으로 들어와 냄비에 빠짐 | 굴뚝으로 몰래 넣은 **링크** → 셋째는 누르지 않고 「신고·차단」 → 늑대가 「차단 냄비」에 풍덩, 픽셀로 흩어져 사라짐 | 누르지 않기·신고하기 |
| 셋째만 살아남는 결말 | 세 형제가 **각자의 장점으로** 동네를 지킴(첫째: 빠르게 알리기 / 둘째: 설정 돕기 / 셋째: 확인 질문 가르치기) | 공동체 |

### 1-4. 표현 수위 원칙
- 늑대는 무섭기보다 **얄밉고 우스운** 사기꾼(후드 입은 길쭉한 늑대). 냄비 장면에서 다치는 묘사 없음 — 픽셀 조각으로 흩어지며 「차단됨」 도장.
- 실제 회사·앱 이름, 실제 전화번호·주소·URL은 쓰지 않는다. 링크는 「▶ 눌러서 확인」 글자만.
- 「AI」는 나쁜 것으로 그리지 않는다. 늑대가 AI를 **흉내에 악용**했을 뿐이고, 둘째의 기술은 결말에서 이웃을 돕는 힘이 된다.

## 2. 등장인물 디자인

모든 캐릭터·사물은 **잉크색 4px 윤곽선(stroke-linejoin/linecap round)** 의 「스티커」 화풍으로 통일한다. 그림자는 바닥의 납작한 타원(잉크색 18% 불투명).

### 2-1. 돼지 공통 (JS 팩토리 `makePig(kind)`로 생성)
- 기준 크기: 클로즈업(카메라 배율 1)에서 키 약 190(머리 반지름 46, 몸통 타원 rx 58 ry 52)
- 부위: 몸통, 머리, 귀 2(삼각형 둥글게, 점프 후 0.2초 늦게 따라 흔들림), 주둥이 타원 + 콧구멍 2, 눈 2(깜빡임), 볼 홍조, 팔 2(그룹 회전으로 자세), 다리 4(걷기 때 위상 교차)
- 표정 상태: `smile`, `proud`, `worry`, `shock`(눈 커짐·입 O), `laugh`(눈 ^^), `relief` — 입 path와 눈 모양만 바꿔 끼운다
- 공통 상시 움직임: 숨쉬기(세로 1.5% 스케일, 주기 2.4초, 형제마다 위상 다름), 깜빡임(약 3.1초마다 0.12초, 형제마다 어긋나게)
- 걷기: 몸통 위아래 반동(주기 0.42초) + 다리 교차 회전 ±18° + 살짝 앞으로 기울기 4°
- 달리기: 걷기의 2배 속도, 기울기 10°, 발밑 먼지 점 3개

| 형제 | 몸 색 | 구분 소품 | 강조색 |
|---|---|---|---|
| 첫째 | `--pig` | 노란 캡 모자(뒤로 씀) | `--note` 노랑 |
| 둘째 | `--pig` | 청록 둥근 안경 + 손목에 빛나는 스마트워치 | `--tech` 청록 |
| 셋째 | `--pig` | 테라코타 목도리 | `--brick` 테라코타 |

- 실루엣만 봐도 구분되도록 소품의 위치가 서로 다르다(머리 위 / 얼굴 / 목).

### 2-2. 엄마 돼지 (가면 화면에만 등장)
- 꼬불꼬불한 머리 + 진주 목걸이. 진짜 엄마는 등장하지 않는다(「흉내」만 나온다).

### 2-3. 늑대 「흉내쟁이」
- 몸: 길쭉한 회보라(`--wolf`) 몸, 어두운 후드(`--wolf-dark`), 후드 위로 뾰족 귀 2개, 긴 주둥이, 노란 눈, 능글맞은 웃음, 꼬리(상시 좌우 흔들림 ±8°, 주기 1.8초)
- 핵심 소품: **「가면 화면」** — 셀카봉 끝에 달린 둥근 화면. 화면에 흉내 낼 얼굴(둘째, 엄마)이 뜬다.
  - 가짜 표시: 화면 테두리 `--fake` 마젠타, 주사선 3줄이 위아래로 흐름, 얼굴 사본 2장(마젠타·청록)이 ±2px 어긋나며 떨림(글리치)
  - 들킬 때: 떨림이 커지고(±8px) 금이 그어진 뒤(stroke-dashoffset), 가면 반쪽이 떨어져 늑대 얼굴이 드러남
- 늑대의 말풍선: **마젠타 점선 테두리** — 「가짜 목소리」의 시각 기호. 진짜 말풍선은 흰 바탕 + 잉크 실선.

## 3. 화면 구성 규칙 (색·글자·안전 영역)

### 3-1. 색 (CSS 변수와 JS 상수 `C`에 똑같이 둔다)

| 이름 | 값 | 쓰임 |
|---|---|---|
| `--night` | `#172036` | 밤하늘, 무대 바깥 배경 |
| `--dusk` | `#2b3a64` | 저녁 하늘 |
| `--dawn` | `#ffd9b8` | 새벽 하늘(결말) |
| `--paper` | `#fbf3e4` | 크림 종이, 메시지 카드, 실내 벽 |
| `--ink` | `#2a2233` | 윤곽선, 본문 글자 |
| `--pig` / `--pig-shade` | `#f6a9b9` / `#e48aa0` | 돼지 |
| `--note` | `#ffd45c` | 첫째·포스트잇 |
| `--tech` | `#35c4c0` | 둘째·스마트 패널 |
| `--brick` / `--brick-dark` | `#d4643c` / `#a8472a` | 셋째·벽돌, 「차단됨」 도장 |
| `--wolf` / `--wolf-dark` | `#5d5a7a` / `#3b3852` | 늑대 |
| `--fake` | `#ff4f9a` | 가짜·위험(가면, 가짜 말풍선, 가짜 문자) |
| `--safe` | `#7ee0b2` | 안전·확인됨(✓, 방패, 켜지는 창) |
| `--glow` | `#fff2b3` | 창문 불빛, 가로등 |

- 색 온도 흐름: **저녁 남색(시작) → 깊은 밤(위기) → 새벽 복숭아 → 크림(결말)**. 위기의 강조색은 마젠타, 해결의 강조색은 민트.
- 한 화면에 강조색은 많아야 2개(해당 형제 색 + 마젠타 또는 민트).

### 3-2. 글자
- 글꼴: `"Apple SD Gothic Neo","Malgun Gothic","맑은 고딕","Noto Sans KR","Nanum Gothic",system-ui,sans-serif` (외부 글꼴 없음)
- SVG 안 글자 위계(viewBox 단위):
  - 제목·메시지 헤드라인: 96~120, 굵기 900, 자간 -3
  - 장면 헤드라인: 56~64, 굵기 800, 자간 -2
  - 장(章) 태그: 22, 굵기 800, 자간 4, 둥근 알약 모양 바탕(해당 형제 색) — 예 「01 · 쉬운 문」
  - 라벨·말풍선: 28~34, 굵기 700
  - 정보 칩 숫자: 44~56, 굵기 900 (예 「시도 3번」, 「97%」, 「1 → 24」)
- **핵심 정보 글자는 SVG에서 28 이상**으로 한다(휴대폰에서 겨우 보이는 하한). 그보다 작은 글씨는 장식용만.
- 자막은 HTML(4장 참고), 줄바꿈 `word-break: keep-all`.

### 3-3. 안전 영역 (자막이 그림을 가리지 않게 — 참고작 GPT의 약점 대응)

```
y   0 ~  40 : 여백
y  40 ~ 740 : 행동 영역 — 인물·집·말풍선·정보 칩은 전부 여기
y 650        : 땅(거리) 기준선, 650~740은 보도(발·그림자 정도만)
y 760 ~ 880 : 자막 띠 — 중요한 그림·글자를 두지 않는다
x  64 ~1536 : 좌우 안전 여백
```
- 장 태그 위치: (64, 64) 왼쪽 위 고정.
- 정보 칩(인셋 카드): 오른쪽 위 (1080~1480, 90~330) 고정 자리.
- 말풍선은 말하는 인물 머리 위 행동 영역 안에서만 열린다. 화면 밖으로 나가면 꼬리 방향을 바꿔 안쪽으로 연다(좌표를 미리 정해 둔다, 자동 측정 쓰지 않음).

### 3-4. 정보 밀도 규칙 (참고작 Opus의 「정보 과밀」 약점 대응)
- 한 순간에 화면의 글자 덩어리는 **최대 3개**: 장 태그 1 + (말풍선 또는 라벨 묶음 또는 정보 칩) 1 + 자막 1.
- 셋째 집 설명 라벨 4개는 **한 번에 하나만 밝게**, 앞의 것은 50%로 낮추고, 다 쌓이면 벽돌 위 작은 아이콘으로 접힌다.
- 인물끼리 겹치지 않게 같은 줄의 인물 간격은 최소 220(클로즈업 기준). 결말 장면의 세 형제 간격 280.

#### S1 계정이라는 두 번째 집 (5.0~11.4)

- 6.8~7.6: 위에서 휴대폰 세 대가 떨어져 손에 착지(착지 순간 휴대폰 세로 0.85 찌그러짐 → 복원). 화면에 「새 계정 만들기」 빛.

- 8.3~10.4: 각 휴대폰에서 형제 색 점선으로 **집 설계도 윤곽**이 위로 그려짐(stroke-dashoffset). 첫째 것은 대충 삐뚤빼뚤, 둘째 것은 반듯한 사각 + 회로 점, 셋째 것은 벽돌 줄눈까지 촘촘 — 그리는 속도도 첫째가 제일 빠르고 셋째가 제일 느림(성격 복선).
- 10.6~11.4: **휙 넘기기 전환** — 전체가 왼쪽으로 빠르게 미끄러지고(`in3`) 가로 속도선 6줄, S2 거리의 첫째 집 터가 오른쪽에서 들어와 멈춤(`out3`).
- 자막 C2, C3.

#### S10 굴뚝의 링크 (67.6~73.4) — 셋째 집 단면도

- 72.3~72.7: 냄비 위에 **「차단됨」 도장**이 쾅(크기 2.2→1, 회전 -12°, `--brick-dark` 이중 테두리). 냄비 속에서 늑대 색 작은 사각 픽셀 14개가 흩어져 올라가며 사라짐.
- 72.6~73.3: 세 형제가 함께 점프(찌그러짐·늘어남), 첫째·둘째가 셋째에게 엄지.

## 6. 움직임 원칙

참고작 GPT의 약점(반복 루프 + 장면 페이드 = 슬라이드쇼)을 피하고, 참고작 Opus의 강점(사건을 움직임으로 보여 줌)을 더 다듬는다.

1. **사건은 반드시 움직임으로**: 집이 지어지는 것(쪽지·패널·벽돌), 무너지는 것(날아감·떨어짐), 속는 것(파형 → 막대 → 97%), 막아 내는 것(튕겨 나감), 해결(신고 → 냄비 → 도장), 나눔(물결·선·카드가 창으로)이 모두 화면에서 일어난다. 자막은 이를 설명할 뿐 대신하지 않는다.
2. **예비 동작(anticipation)**: 늑대가 불기 전 들이쉬기, 점프 전 쪼그림, 셋째가 팔 뻗기 전 0.2초 당김.
3. **찌그러짐과 늘어남(squash & stretch)**: 벽돌·휴대폰 착지, 점프, 가짜 문자 부딪힘, 늑대가 굴뚝에 빠질 때.
4. **겹침과 따라옴(overlap, follow-through)**: 귀는 몸보다 0.15~0.2초 늦게, 멈출 때 몸이 앞으로 쏠렸다 돌아옴, 형들이 셋째 팔에 막혀 출렁.
5. **시차 출발(stagger)**: 같은 종류가 여럿 움직일 때 절대 동시에 움직이지 않는다(0.05~0.2초 간격).
6. **이징 규칙**: 등장 `outBack`(지나침 1.4~1.7), 퇴장 `in3`, 카메라 `inOut3`, 떨어져 닿기 `land`(아래 함수), 탄성 `spring`. 선형은 입자 흐름·주사선에만.
7. **장면 전환은 이어지게**: 조리개(S0→S1), 휙 넘기기(S1→S2), 카메라 연속 이동(S2~S10), 늑대 카드 밀어 넣기·빼기(S5), 화면 분할(S8), 단면도(S10), 줌아웃(S10→S11), 종이 와이프(S11→S12). 단순 검은 화면 페이드는 쓰지 않는다.
8. **살아 있는 정지 화면**: 멈춘 듯한 순간에도 숨쉬기·깜빡임·꼬리·별·창 불빛·아주 느린 카메라 밀기가 있다.

이징 함수(구현 기준):
```
clamp(v,a,b), lerp(a,b,p), prog(t,a,b)=clamp((t-a)/(b-a),0,1)
out3(p)=1-(1-p)^3      in3(p)=p^3      inOut3(p)=p<.5?4p^3:1-(-2p+2)^3/2
```

### 7-2. 시간 엔진 (참고작 Opus의 「프레임 델타 누적 → 느린 기기 슬로모션」 약점 대응)
- **실제 시계 기준**: 재생 중 `t = baseT + (performance.now() - baseNow) / 1000`. 재생·재개·탐색 때만 `baseT`, `baseNow`를 다시 잡는다. 느린 기기에서도 89초는 89초다(프레임이 떨어지면 건너뛸 뿐).
- **모든 그림 상태는 t의 순수 함수**: `render(t)`가 매 프레임 각 요소의 위치·회전·불투명도를 t에서 새로 계산한다. 이전 프레임 값을 누적하지 않는다. → 탐색·일시정지·다시 보기·디버그 시각 지정이 모두 정확하다.
- 장면 등록: `SCENES = [{id, a, b, el, update(t)}]`. `render(t)`는 `[a-0.6, b+0.6]` 안의 장면만 `update`하고, 범위 밖 장면 그룹은 `display:none`(성능). 장면 사이 겹침 구간에서 불투명도로 교차.
- `requestAnimationFrame` 고리는 재생 중에만 돈다. 정지 상태에서는 상태가 바뀔 때만 `render` 한 번.
- 속성 쓰기 도우미: `tf(el, x, y, r, sx, sy)` → `transform="translate(x y) rotate(r) scale(sx sy)"`, 숫자는 소수 둘째 자리까지. 같은 값이면 다시 쓰지 않는 캐시(문자열 비교).

### 7-3. 재생기 (참고작 GPT 수준 + 보완)
- 상태: `cover` → `playing` ⇄ `paused` → `ended` → (다시 보기) `playing`.
- **처음 화면(덮개)**: S0의 t=3.6 장면을 멈춘 그림으로 그린 위에 반투명 어둠 + 가운데 큰 둥근 재생 버튼(지름: 무대 너비의 9%, 최소 64px, `--paper` 바탕 + 잉크 ▶), 버튼 아래 작은 안내 「약 89초 · 소리 없음 · 스페이스바로 멈춤」. 덮개 글은 무대 크기에 비례(`cqw`)하므로 휴대폰에서도 겹치지 않는다(참고작 GPT의 「휴대폰 표지 안내 문구 겹침」 대응). 안내 글은 무대 너비 480px 미만이면 숨긴다.
- **조작 막대**(무대 아래, 무대와 같은 너비, 높이 48px): 재생/일시정지 버튼(44×44 이상, `aria-label` 「재생」/「일시정지」로 바뀜) · 현재 시간 `00:42` · 탐색 막대(`input type=range`, 0~89, step 0.1, `aria-label="재생 위치"`, `aria-valuetext="42초, 1234"`처럼 장면 이름 포함) · 전체 시간 `01:29`. 탐색 막대 위에 장면 시작 위치 눈금 13개(작은 세로선, `title`에 장면 이름).
- **탐색**: `input` 중에는 멈춘 채 그 시각을 그림, `change`에서 원래 재생 중이었으면 이어서 재생. 끝까지 끌면 `ended` 상태.
- **끝(89.0초)**: 마지막 프레임 위에 반투명 어둠 + 「다시 보기 ↺」 버튼(재생 버튼과 같은 모양) + 작은 글 「처음부터 다시 재생합니다」. 버튼에 자동 초점. 누르면 t=0부터 재생(모든 상태가 t의 함수라 별도 초기화 불필요, 단 자막·알림 캐시는 비움).
- **키보드**: 스페이스·K = 재생/일시정지(덮개·끝 화면에서는 재생/다시 보기), ←/→ = 5초 뒤/앞, Home = 처음, R = 다시 보기. 초점이 버튼·탐색 막대에 있을 때는 그 요소의 기본 동작과 겹치지 않게 처리(버튼 위 스페이스는 버튼이 처리, 탐색 막대 위 ←/→는 막대가 처리).
- **탭이 숨으면 자동 일시정지**(`visibilitychange`). 돌아와도 자동 재생하지 않고 일시정지 표시 유지.
- 일시정지 중에는 무대 가운데에 작은 ❚❚ 표시가 0.6초 떴다 사라짐.

### 7-4. 반응형
```css
.app      { min-height:100vh; min-height:100svh; display:grid; place-content:center; gap:10px; padding:16px; }
.viewport { position:relative; container-type:inline-size;
            width: min(100vw - 32px, (100vh - 100px) * 16 / 9); }
@supports (height:100svh){ .viewport { width: min(100vw - 32px, (100svh - 100px) * 16 / 9); } }
.stage    { position:relative; width:100%; aspect-ratio:16/9; overflow:hidden; border-radius:14px; }
svg#film  { position:absolute; inset:0; width:100%; height:100%; display:block; }
```
- `dvh`는 쓰지 않는다(내장 브라우저 크기 흉내에서 작게 그려진 전례).
- 무대 최소 너비 288px(320px 화면 − 여백 32px).
- **자막 위치**:
  - 가로 화면: `.caption`을 `.viewport` 안에서 `position:absolute; left:50%; bottom:3.5%; transform:translateX(-50%)`, 최대 너비 84%, 글자 `clamp(15px, 2.35cqw, 36px)`, 굵기 600, 줄 간격 1.45, 흰 글자 + `rgba(16,20,36,.84)` 바탕, 모서리 .6em, 위아래 .45em 좌우 1em.
  - 세로로 긴 화면(`@media (max-aspect-ratio: 4/5)`): 자막을 무대 **아래**로 꺼내 `position:static`, 너비 100%, 글자 16px, 최소 높이 3.2em(두 줄 자리 확보 → 자막이 바뀌어도 조작 막대가 위아래로 출렁이지 않음). (참고작 GPT의 「휴대폰에서 자막 작음」 대응)
- 자막 바뀜: 0.25초 불투명도 교차(이전 글 사라짐 → 새 글 나타남), 자막이 없는 구간에는 바탕도 숨김.
- 4K 큰 화면에서도 무대 최대 너비 제한 없이 비율 유지(벡터라 선명).

### 7-5. 접근성
- `<svg>`에 `<title id="ft">`(작품 제목)과 `<desc id="fd">`(한두 문장 줄거리). 장식 그룹은 `aria-hidden="true"`.
- 화면 자막 요소는 `aria-hidden="true"`, 화면 읽기용 `#live`(`aria-live="polite"`, 화면에서 숨김)에 같은 자막을 넣는다. **재생 중 자막이 바뀔 때만** 넣고, 탐색 막대를 끄는 동안에는 넣지 않으며 끌기가 끝나고 0.3초 뒤 현재 자막을 한 번 넣는다. S12에서는 C24를 넣는다.
- 모든 버튼 `type="button"`, 초점 표시 `outline:3px solid var(--note); outline-offset:4px`.
- 색만으로 뜻을 전하지 않는다: 가짜는 마젠타 + 점선 + 글리치, 확인됨은 민트 + ✓.
- 대비: 자막 흰 글자 대 어두운 바탕 7:1 이상, 메시지 카드 잉크 대 크림 10:1 이상.

### 7-6. 움직임 줄이기 (`prefers-reduced-motion: reduce`)
- `RM` 값을 `matchMedia`로 읽고 바뀌면 즉시 반영(`change` 이벤트).
- 길이·자막 시각은 그대로(내용 동기 유지). 바뀌는 것:
  - 카메라 이동 → 0.35초 불투명도 교차로 **끊어 옮기기**(목표 카메라 값으로 바로, 사이에 무대 어둠 0.25 깜빡)
  - 화면 흔들림·휙 넘기기 속도선·조리개 → 없음 / 단순 교차
  - 글리치 떨림 → 고정된 어긋남(움직이지 않음)
  - 입자(바람 곡선, 가짜 문자, 픽셀, 물방울) → 개수 1/3, 회전 없음
  - 숨쉬기·꼬리·별 반짝임 같은 상시 반복 → 멈춤
- 디버그용으로 주소 해시 `#rm`이 있으면 줄인 움직임을 강제로 켠다.

### 7-7. 디버그 진입 (3단계 스크린숏 검토용, 최종본에 남겨도 해롭지 않음)
- 주소 해시 `#t=48.5` → 덮개를 숨기고 그 시각을 일시정지 상태로 그리고 자막도 표시. 예: `index.html#t=48.5`
- `#t=48.5&rm` → 줄인 움직임으로 그 시각
- 해시 해석 실패는 조용히 무시(콘솔 오류 없음).

### 7-8. 콘솔 오류 방지 체크
- `getBBox`·`getComputedTextLength` 같은 측정은 쓰지 않는다(`display:none` 상태에서 브라우저에 따라 예외). 말풍선·칩 크기는 글자 수로 미리 계산: 한글 1자 ≈ 글자 크기 1.0, 영문·숫자·기호 ≈ 0.6.
- 존재하지 않는 id 참조 금지 — 초기화 끝에 필요한 요소가 다 있는지 확인하고, 없으면 그 장면만 건너뛴다(예외 없이).
- `NaN`이 `transform`에 들어가지 않게 `tf`에서 유한수 검사.
- `localStorage`, 외부 요청, `eval` 쓰지 않음.
- 파비콘 `data:,` 지정.

### 7-9. 성능
- SVG 필터(`feGaussianBlur` 등)는 정적인 빛 번짐 2개 이하만, 애니메이션 대상에는 쓰지 않는다. 빛은 반투명 원 겹치기로.
- 프레임당 바꾸는 속성 수를 줄이도록 그룹 단위로 `transform`을 준다.
- 화면 밖 장면 그룹 `display:none`.
