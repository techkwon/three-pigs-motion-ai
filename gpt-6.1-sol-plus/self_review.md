# 「마감 늑대와 빈칸 있는 집」 자기 검토

## 검토 범위와 판단

`_review/desk/`의 21장과 `_review/mob/`의 3장, 합계 24장을 모두 검토했다. `관찰.txt`와 두 폴더의 `_log.txt`, `index.html` 전체, `own_brief.md`, `_ref/과제지시문.md`, `_ref/평가요약.md`를 대조했다. 아래 코드 위치는 이번 검토 시점의 `index.html` 줄 번호다. 사진의 시각은 파일 이름을 기준으로 하되, 운영자가 기록한 촬영 오차를 고려했다. 특히 `t00070.jpg`는 실제 약 70.67초다.

현대적 주제와 원작의 뼈대는 전달된다. 세 형제의 식별, 별도 HTML 자막, 차분한 색상, 첫째의 과적과 둘째의 처리 한계를 구분한 설정도 유효하다. 그러나 **설계서에서 약속한 사건을 실제 행동으로 보여 주는 수준에는 미치지 못한다.** 후반은 카드와 표지가 자동으로 배치되는 설명 화면에 가깝고, 기존 집과 새 일정판이 중첩되어 핵심 의미를 방해한다. 데스크톱 자막은 읽히지만 모바일의 그림 안 정보는 지나치게 작다.

평가 항목별 판단은 다음과 같다. 별도의 채점 기준이 없으므로 임의의 점수는 붙이지 않는다.

## 수정 우선순위

심각도 **높음**은 이야기 이해나 핵심 행동의 판독을 방해하는 문제, **중간**은 장면 연결과 모션의 설득력을 떨어뜨리는 문제, **낮음**은 보조 정보의 완성도 문제다. 같은 심각도 안에서도 아래 순서대로 수정한다.

### 1. 공동 일정판과 기존 소품이 겹쳐 해결 장면의 중심을 흐린다

- **심각도:** 높음
- **위치:** 59.2~84초. `desk/t00060.jpg`, `t00065.jpg`, `t00070.jpg`, `t00075.jpg`, `t00080.jpg`, `t00085.jpg`, `zz_end.jpg`. 코드 274~282줄(기존 일정판), 304~330줄(공동 일정판·표지·깃발), 378~380줄(기존 집 퇴장), 510~541줄(후반 배치).
- **문제:** 60초에는 새 판이 반투명하게 기존 지붕·일정판·종이 위에 얹힌다. 65~75초에는 아래로 삐져나온 기존 작업 칸과 ‘쉼’이 남아, 휴식 영역이 중복된다. 새 ‘쉼’ 팻말은 ‘함께 쉬는 시간’ 문장 가운데를 덮는다. 결말에서도 축제 깃발이 업무 칸의 글자·완료 표시 앞을 지난다. 이 겹침은 인물끼리 겹치지 않는 것만으로 해결되지 않는다. 설계서 3.1·4절의 정보량 제한과 11.1절의 해결 장면 판독 기준을 충족하지 못한다.
- **수정 방법:** 59~60초에 기존 일정판을 접거나 뒤로 물려 새 판이 자리 잡을 공간을 만든다. 집 외곽은 남겨도 내부 카드·기존 ‘쉼’·옛 벤치는 교대 시점에 명확히 숨긴다. 휴식은 새 일정판의 한 영역으로 통합하고, ‘쉼’ 팻말을 그 영역의 왼쪽 빈자리 등에 놓아 문장을 가리지 않게 한다. 깃발 줄은 일정판의 위쪽으로 올리거나 판 바깥 양옆으로 나누고, 완료 표시를 위한 여백을 확보한다. 수정 후 60·65·70·75·82초에 모든 핵심 글자가 독립적으로 읽혀야 한다.

### 2. 해결의 주역인 손과 카드가 몸 뒤에 숨고, 합의·업무 완료가 자동 변화처럼 보인다

- **심각도:** 높음
- **위치:** 60~79.5초. `desk/t00060.jpg`, `t00065.jpg`, `t00070.jpg`, `t00075.jpg`, `t00080.jpg`. 코드 79~81줄(그룹 순서), 316~328줄(해결 소품), 493~506줄(인물), 514~540줄(선별·분담·완료). 설계서 5절 장면 8~9, 7.1절.
- **문제:** `solution`이 `characters`보다 먼저 그려져 선별 카드가 몸에 가린다. 60초의 ‘리본’ 카드도 인물 뒤로 일부만 보인다. 고개 끄덕임·‘이번엔 생략’ 표지는 코드에 있지만, 제공된 60·65초 사진 사이의 짧은 구간이라 스크린숏만으로 그 판독성을 입증할 수 없다. 더 근본적으로 분담 카드의 출발점은 고정 좌표이며 실제 기존 일감과 연결되지 않는다. 75초에 안내판·무대·리허설이 나타나고 곧 체크가 붙지만, 각 형제가 그것을 마치는 행동은 없다. 결국 ‘함께 덜고 나눠 마쳤다’는 핵심을 자막이 대부분 설명한다.
- **수정 방법:** 작업용 카드와 손의 전후 관계를 분리해 카드가 가슴 앞이나 얼굴 아래의 빈 공간에서 보이게 한다. 60~65초를 ‘두 추가 카드 제시→세 형제의 명확한 동의→생략 표지→상자에 넣고 손 놓기’로 나누고, 각 결과가 짧게 정지하도록 한다. 65~70초에는 화면에 남아 있는 필수 카드에서 세 칸으로 이동시킨다. 칸의 색과 담당 형제의 위치·소품을 연결한다. 현재 왼쪽 파란 형제 위에 주황 칸, 가운데 주황 형제 위에 파란 칸이 놓여 있어 담당 관계를 색만으로 추론하기 어렵다. 75~77초에는 각 형제의 마지막 작업 동작 또는 명확한 시간 경과 뒤에 완료 표시를 붙인다. 84초는 유지하고 장식 등장 시간을 줄여 이 행동에 배정한다.

### 3. 기계의 처리 흐름과 재활용이 불분명해 자동화의 의미가 약해진다

- **심각도:** 높음
- **위치:** 20~25초, 43~49초, 65~70초. `desk/t00020.jpg`, `t00025.jpg`, `t00045.jpg`, `t00050.jpg`, `t00065.jpg`, `t00070.jpg`. 코드 257~272줄(기계), 402~422줄(처리·막힘), 457~464줄(과적), 512~513·525~530줄(분담 레일·카드).
- **문제:** 정상 처리에서는 종이가 기계 앞을 지나가는 인상이 강하다. 이동 카드의 경로는 투입부에서 레일까지이며 출력함까지 이어지지 않는다. 출력 더미와 입력 대기 더미는 별도 시각 조건으로 나타나므로 한 장이 처리되어 쌓이는 관계가 약하다. 위기에서는 입김 카드·과적 카드·컨베이어 카드가 겹쳐, 입력량 증가보다 종이 폭풍이 먼저 읽힌다. 후반 분담 레일은 기존 기계와 분리된 곡선으로 나타난다. 톱니는 `Math.min(t,47.6)`에서 멈추고 운반 카드는 48.6초 이후 재가동되지 않아, 설계한 ‘기계를 공동 일정에 연결해 천천히 다시 쓴다’는 결과가 구현되지 않았다.
- **수정 방법:** 같은 카드의 상태를 투입 대기→투입구 안으로 들어감→레일 이동→출력함 정착으로 연결한다. 정상 장면은 소수 카드로 전체 경로를 한 번 보여 주고, 위기는 입력 간격만 줄여 출력이 따라가지 못하는 차이를 강조한다. 과적 더미가 정지한 레일과 연결되도록 한다. 65초 이후에는 기존 레일의 일부가 분담 경로가 되는 형태를 보여 주고, 톱니와 소수 카드가 느린 일정 간격으로 다시 움직이게 한다. 새 설명문을 추가하기보다 종이 수와 이동 경로를 정리한다.

### 4. 모바일에서 핵심 그림과 표지가 너무 작아 자막 의존도가 높다

- **심각도:** 높음
- **위치:** `mob/00_cover.jpg`, `mob/t00012.jpg`, `mob/t00040.jpg`. 데스크톱의 원경인 `desk/t00001.jpg`, `zz_replay2s.jpg`도 관련된다. 코드 24~30·48줄(비율·글자·모바일 CSS), 85~95줄(표지), 334~356줄(카메라).
- **문제:** 375px 화면에서 무대는 약 349×196px다. 모바일 자막 17px와 버튼은 충분히 읽히지만, 12초 화면의 ‘추가’·‘축제 안내’와 40초 늑대의 ‘오늘까지’는 작다. 영상 좌표의 36px 글자는 근접 구도에서도 대략 11px 수준이다. 설계서의 ‘중요 표지는 근접 구도로’라는 요구가 충족되지 않았다. 표지에서는 부제와 설명이 더 작아진다. 같은 16:9 화면을 축소한 것만으로 반응형 이야기 화면을 확보한 것은 아니다.
- **수정 방법:** 16:9와 비균등 확대 금지는 유지하되, 좁은 화면에는 중요한 행동을 더 크게 담는 카메라 키를 둔다. ‘추가’는 카드 받기 순간, ‘쉼’은 휴식 확보 순간의 중심에 크게 보여 준다. 장면 전체를 담아야 한다면 읽어야 하는 표지를 줄이고 기호와 손동작으로 뜻을 보완한다. 표지의 부제·설명은 HTML 안내로 옮기고 제목과 세 형제만 남기는 간결한 구도를 만든다. 375px와 320px에서 원본 크기로 확인해 자막 없이도 요청 증가와 집의 실패를 구분할 수 있어야 한다.

### 5. 셋째의 한계와 ‘함께 멈추는’ 전환을 체감할 시간이 부족하다

- **심각도:** 중간
- **위치:** 53~65초. `desk/t00055.jpg`, `t00060.jpg`, `t00065.jpg`. 코드 374~377줄(셋째 집 압력), 461~464줄(빈칸 쪽 과적), 491~511줄(판단·일정판), 530줄(업무 칸 등장). 설계서 장면 7~8.
- **문제:** 55초에는 종이가 일정판을 덮지만, 인물 표정과 셋째 집의 약한 기울기만으로 ‘셋째의 방법도 혼자서는 부족하다’는 반전이 분명하지 않다. 57~60초는 세 인물이 비슷한 팔 자세를 취하고, 서로를 보는 동작은 없다. 59.2초에 새 일정판이 먼저 나타나지만 업무 칸은 65.7초 이후에 나오므로 60·65초 화면의 큰 빈 판이 먼저 시선을 차지한다. 의도한 ‘쉬어야 하는 빈칸’과 ‘아직 내용이 나타나지 않은 판’도 혼동된다.
- **수정 방법:** 카드가 셋째의 마지막 빈칸에 닿는 순간을 하나의 뚜렷한 사건으로 잡고, 셋째가 막으려다 손을 멈추게 한다. 이어 셋이 카드를 내려놓고 서로를 향해 고개를 돌리는 정착 시간을 둔다. 새 일정판은 실제 일감을 나누는 순간에 맞춰 펼치거나, 처음부터 기존 필수 카드가 남아 있는 판을 재정리하게 한다. 휴식 칸은 테두리·타이머로 일관되게 식별해 큰 빈 배경과 구분한다.

### 6. 집이 접히는 대신 전체가 압축되어 글자와 문까지 납작해진다

- **심각도:** 중간
- **위치:** 건축 7~9초·17.2~19초·26.2~27.5초, 붕괴 38.05~39.5초. `desk/t00040.jpg`, `mob/t00040.jpg`. 코드 231~245줄(집 구조), 369~387줄(변형). 설계서 7.1절.
- **문제:** 건축은 구조 전체의 가로 스케일 하나로 진행된다. 붕괴는 `scale(..., 1-.72*collapse)`로 벽·안내판·종이·문을 함께 세로 압축한다. 40초 화면의 ‘다 맡을게’와 ‘축제 안내’가 눌린 것은 접이식 구조의 결과보다 그림 전체를 찌그러뜨린 효과로 보인다. 지붕 아래의 큰 종이들은 상대적으로 정상 비율이라 물체 간 변형 규칙도 다르다.
- **수정 방법:** 벽·지붕·기둥·내부 소품의 변형을 분리한다. 건축은 벽이 먼저 열리고 지붕이 뒤이어 자리 잡게 한다. 붕괴는 카드 접촉→지붕 하강·회전→옆벽 접힘→바닥에 정착 순서로 만든다. 글자는 소품의 강체 이동을 따르게 하고, 종이도 접힌 면에 붙어 있거나 떨어지게 한다. 38.5·39.5·40초를 이어 비교해 접힘의 원인과 최종 형태를 확인한다.

### 7. 피신은 문 통과와 접지가 부족해 거리 위를 미끄러지는 이동에 가깝다

- **심각도:** 중간
- **위치:** 39.8~43초, 49.4~53초, 60~61초. `desk/t00040.jpg`, `t00045.jpg`, `t00050.jpg`, `t00055.jpg`. 코드 188~200줄(보행 자세), 381~386줄(문), 484~506줄(이동).
- **문제:** 두 번의 피신에서 인물 이동은 실제로 존재하고 간격도 확보된다. 그러나 x좌표 이동과 문 열기가 별도로 계산된다. 첫째는 집 왼쪽 앞에서 출발해 둘째 집 앞에 서며, 문턱을 통과해 보호받는 과정은 없다. 발 주기는 위치 이동의 가속·감속과 무관해, 속도가 거의 0인 구간에도 달리는 자세가 나온다. 60~61초에는 세 형제의 위치가 바뀌는데 보행 자세가 없어 발을 붙인 채 이동한다. 사진만으로 정확한 발 미끄러짐 양을 단정할 수는 없지만 코드상 결합이 부족하다.

## 4단계 수정 완료의 기준

우선 1~4번을 고쳐 해결 장면의 의미와 모바일 판독성을 확보하고, 5~10번의 사건 연결·동작을 보완한다. 마지막에 표지를 정돈한다. 장면 추가나 재생기 전면 교체보다 현재 84초 안에서 원인·손의 행동·결과의 정착을 보이게 하는 데 집중한다.

같은 화면 크기와 시각을 다시 캡처하되, 정지 사진만으로 모션의 자연스러움을 판정하지 않는다. 12~16초, 37~43초, 44~53초, 55~65초, 65~77초를 연속으로 확인한다. 최종적으로 **자막을 가린 상태에서도 추가 요청→과적→피신→공동 선별→분담→휴식→필수 일 완료가 구분되고, 자막을 켜면 그림과 정확히 맞아야 한다.**

이번 단계에서는 검토문만 작성했으며 `index.html`, `own_brief.md`, `_ref/`, `_review/`는 수정하지 않았다.

### 명령줄 점검 결과와 확인 범위

- 인라인 JavaScript를 Node의 `vm.Script`로 구문 검사했다. 맨 위 주제·장면·메시지 주석, 84초 길이, 외부 로딩·오디오 부재, 정적·동적 SVG 내부 참조와 ID를 점검했다. 바뀐 후반 장면 시작 시간은 맨 위 주석에 갱신했다.
- 브라우저를 실행하지 않고 최소 DOM 모형에서 스크립트를 평가했다. 일반/좁은 화면 × 일반/움직임 감소의 네 조합에서 0~84초를 0.1초 간격으로 계산한 3,364개 표본에 실행 예외나 `NaN`·`Infinity` 속성이 없었다.
- 대표 시각 23개 × 네 조합, 총 92회에서 직접 계산한 상태와 84초→0초를 거쳐 돌아온 상태의 속성·텍스트가 일치했다. 기존/공동 일정판 교대, 최종 마감 카드의 목적지, 마지막 3초의 주요 그림과 카메라 고정도 점검했다.
- 같은 DOM 모형에서 일시정지 시간 유지, 정지 중 탐색, 재생 중 탐색 후 재개, 끝으로 탐색, 종료 후 뒤로 탐색, 다시 보기 3회, 숨은 탭 정지, 일반 영역의 Space 전환과 자막 구간의 0~84초 연속성을 확인했다.
