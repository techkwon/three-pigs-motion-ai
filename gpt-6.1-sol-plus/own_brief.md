## 1. 작품의 중심

**로그라인:** 축제를 준비하는 돼지 삼형제. 첫째는 모든 부탁을 받고, 둘째는 기계로 더 많은 일을 처리하며, 셋째는 일정에 빈칸을 남긴다. 끝없이 늘어나는 할 일이 ‘마감 늑대’가 되어 두 형제의 준비방을 무너뜨린다. 세 형제는 함께 해야 할 일을 줄이고 나누며, 모두가 숨 쉴 시간을 되찾는다.

**현대적 주제:** 끝없는 추가 요청과 생산성 경쟁 속에서, 일의 양과 속도를 함께 조절하는 삶.

**마지막 문장:** “좋은 집에는, 함께 숨 쉴 빈칸이 있다.”

중학생에게 익숙한 축제 준비를 배경으로 한다. ‘백로그’, ‘워크플로’, ‘번아웃’ 같은 용어는 쓰지 않는다. 빠른 손과 기술은 유용하다. 문제는 처리할 수 있는 양을 생각하지 않고 일을 계속 늘리는 데 있다. 해결은 셋째 혼자 버티는 것이 아니라, 세 형제가 필요한 일을 합의하고 역할과 휴식을 함께 정하는 것이다.

### 원작의 뼈대와 새 의미

| 원작의 요소 | 이 작품에서 보이는 것 | 새 의미 |
|---|---|---|
| 세 형제 | 옷과 소품이 구별되는 세 돼지 | 서로 다른 능력을 지닌 동료 |
| 세 집, 세 선택 | 부탁 종이로 채운 접이식 준비방 / 자동 처리 준비방 / 일정에 빈칸이 있는 준비방 | 전부 받기 / 처리 속도만 높이기 / 여유를 남기기 |
| 늑대와 입김 | ‘오늘까지’, ‘추가’ 종이가 모인 늑대와 종이바람 | 늘어나는 요구와 다가오는 마감 |
| 첫째→둘째→셋째의 피신 | 같은 골목을 따라 실제로 달리는 형제들 | 혼자 해결하려던 방식의 한계 |
| 튼튼한 집과 결말 | 셋째 방에도 일이 밀려오지만, 함께 일의 양과 일정을 바꿈 | 안전은 벽의 두께보다 함께 정하는 방식에서 생김 |

마감 자체를 없애거나, 맡은 필수 업무를 일방적으로 버리는 결말은 피한다. 마지막에도 시계와 필수 과제는 남는다. 불필요한 추가 장식은 **형제들의 합의로 생략**하고, 필수 작업은 나눠 마친다. 빈칸은 남는 시간을 더 많은 일로 채우지 않겠다는 약속이다.

## 3. 화면과 미술

### 3.1 기본 구성

- 영상 무대는 인라인 SVG `viewBox="0 0 1280 720"`, `preserveAspectRatio="xMidYMid meet"`. 영상 자체는 항상 16:9다.
- SVG 아래에 HTML 자막 띠, 그 아래에 재생 조작부를 둔다. 자막을 그림 위에 덮지 않는다. 이 전체 묶음이 하나의 재생기다.
- 영상 내 안전 영역은 `x=56~1224, y=48~656`. 지면은 화면 기준 약 `y=592`. 표지·얼굴·손의 행동은 안전 영역 안에 둔다.
- 본편은 하나의 넓은 세계를 카메라가 따라간다. 세계 좌표에서 준비방 중심은 첫째 `(430, 570)`, 둘째 `(1430, 570)`, 셋째 `(2430, 570)`. 각 방의 폭은 약 440, 높이는 약 300이다.
- 카메라 이동은 세계 그룹의 `translate/scale`로 한다. 자막·조작부·고정 화면 제목은 세계 그룹 바깥에 둔다. 거리 소개와 마지막 전경 외에는 한 방을 크게 보여 준다.
- 2D 정면도에 종이 접힘과 얕은 측면만 더한다. 정교한 원근이나 실제 3D 효과를 목표로 하지 않는다.
- 기본 화면에서 행동 주체 1개, 원인 1개, 결과 1개만 우선 읽히게 한다. 먼 집은 윤곽만 남기고 문자·내부 소품은 숨긴다.

### 3.2 색과 선

| 용도 | 색 | 적용 |
|---|---|---|
| 바탕 | `#FAF6EE` | 따뜻한 무채색, 넓은 여백 |
| 먹색 | `#26213E` | 외곽선·본문·늑대의 중심 덩어리 |
| 첫째 | `#F2AB57` | 주황 옷·접힌 종이 테두리 |
| 둘째 | `#5D86D9` | 파랑 작업복·기계의 면 |
| 셋째 | `#8C74C9` | 보라 조끼·빈칸의 테두리 |
| 빈칸 | `#E7E0F4` | 쉬는 칸, 잔잔한 마지막 배경 면 |
| 위기 | `#BD493F` | 추가 요청 도장·늑대의 눈·과적 경고 |
| 밝은 면 | `#FFFFFF` | 카드·눈·창 일부 |

색상만으로 형제를 구별하지 않는다. 위기에서도 화면 전체를 빨갛게 덮지 않고, 종이와 늑대의 점유 면적을 늘린다. 결말은 같은 바탕에서 카드 간격과 여백이 넓어지는 것으로 평온을 만든다.

외곽선은 화면 기본 배율에서 3px, 내부선은 2px, 둥근 끝·둥근 접합. 종이 모서리 접힘은 단순한 삼각형 한 개. 장식용 노이즈 필터·광택·강한 그림자·상시 파티클은 없다. 바닥 접지 그림자는 낮은 불투명도의 납작한 타원만 사용한다.

### 3.3 캐릭터와 소품

세 돼지의 기본 키는 세계 좌표 약 128. 머리·몸·왼팔·오른팔·다리·표정을 별도 그룹으로 그린다. 귀 두 개, 둥근 코, 콧구멍 두 개, 작은 꼬리로 돼지임을 분명히 한다. 원작을 모르는 사람에게도 세 형제가 같은 종족으로 보이게 한다.

| 인물 | 고유 식별 | 움직임과 감정 | 결말의 행동 |
|---|---|---|---|
| 첫째 | 주황 옷, 옆으로 쓴 모자, 번개 모양 작은 패치 | 손이 먼저 나감. 위기에서 종이를 붙잡다 어깨가 처짐. | 빠른 손으로 추가 장식을 골라 덜어 냄. |
| 둘째 | 파랑 작업복, 둥근 보안경, 사각 공구 주머니 | 레버를 당기고 기계 흐름을 확인함. 막히면 레버를 놓음. | 기계의 카드 레일을 공동 일정판으로 연결함. |
| 셋째 | 보라 조끼, 반원 주머니, 작은 타이머 | 빈칸을 손으로 가리킨 뒤 형제에게 자리를 내줌. 마지막에는 함께 앉음. | 휴식 칸을 고정하고 타이머를 둠. |

위기의 눈썹과 입은 명확하게 바뀐다. 팔을 관통하는 소품이나 몸 전체를 부풀리는 반응은 피한다. 달릴 때 이동, 발 교대, 상체 기울기를 결합하고, 정지하면 발을 지면에 고정한다.

**주요 소품:** 부탁 종이, 첫째의 접이식 방, 둘째의 투입구·레일·출력함이 보이는 기계 방, 셋째의 일정 칸이 보이는 방, 벤치, 원형 시계, 공동 일정판, 축제 안내판, 무대 모형, 리허설 표시.

**종이의 연속성:** 작은 귀퉁이가 접힌 직사각형을 전편의 공통 도형으로 쓴다. 부탁 종이 → 과적 더미 → 늑대의 털·입김 → 합의해 덜어 낸 추가 카드 → 공동 일정판의 정돈된 카드로 이어진다. 문자 읽기 없이도 같은 물체라는 것이 보여야 한다.

**마감 늑대:** 접힌 카드 12~18개와 별도의 귀·긴 주둥이·눈으로 만든 명확한 옆모습. 거대한 말풍선이나 단순 검은 구름으로 보이면 안 된다. ‘오늘까지’ 한 장만 크게 읽히고 나머지는 선과 도장으로 처리한다. 위기는 입김이 카드를 밀고, 그 카드가 집을 덮는 과정이다. 늑대가 뜬금없이 나타나 벽을 부수는 액션은 아니다.

## 4. 글자와 정보량

- 시스템 글꼴: `"Malgun Gothic", "Apple SD Gothic Neo", system-ui, sans-serif`. 외부 글꼴 요청 없음.
- 영상 안 제목 72~84, 핵심 문구 44~52, 꼭 읽어야 하는 표지 36 이상을 기준으로 한다. 긴 영문 장식 문구나 작은 설명문은 넣지 않는다.
- 표지의 제목은 **“마감 늑대와 / 빈칸 있는 집”** 두 줄. 부제는 “아기 돼지 삼형제, 다시 쓰는 이야기”. 작은 크기에서는 부제를 영상 아래 HTML 안내로 옮긴다.
- 영상 너비 600px 미만에서는 장식 표지와 배경 문자를 숨긴다. 중요한 ‘추가’, ‘쉼’, ‘함께’는 근접 구도로 보여 준다. 서사는 한국어 내레이션만 읽어도 따라갈 수 있어야 한다.
- 자막은 HTML 실제 텍스트, 데스크톱 20~24px, 모바일 최소 17px, 줄높이 1.5~1.6. 한 큐에 한 문장, 최대 두 줄을 기본으로 한다. 320px처럼 좁은 화면에서는 글자를 줄이지 않고 세 줄까지 허용한다.
- 자막 띠는 어두운 먹색 바탕·밝은 글자. 가장 긴 자막을 기준으로 최소 높이를 확보해 문장 교체 때 조작부가 튀지 않게 한다. 사용자 글자 확대 시 높이는 늘어날 수 있다.
- 본편 중 별도 장면 번호, 상단 설명 헤드라인, 말풍선은 사용하지 않는다. 대사는 자막의 따옴표로 전달한다. 화면의 ‘오늘까지’, ‘이번엔 생략’, ‘쉼’ 등은 사건에 필요한 소품 글자다.

## 6. 확정 한국어 자막 큐

아래 문장을 단일 데이터 배열로 관리한다. 화면과 접근성 텍스트가 같은 배열을 쓴다. 자막은 한 글자씩 타이핑하지 않는다. 한 번에 보여 주고 정해진 시간 동안 유지한다.

| 7~11.5 | 첫째는 손이 빨랐다. |

| 29~33 | 형들은 그 시간이 아깝다고 생각했다. |

## 7. 움직임의 문법과 제작 기준

### 7.1 원인과 결과를 가진 동작

| 동작 | 설계값과 연출 |
|---|---|
| 종이집 펼치기 | 벽이 힌지를 중심으로 0→90도 열린 것처럼 가로 폭을 변화시키고, 지붕이 뒤이어 내려온다. 각 동작 0.45~0.65초, 순서차 0.12초. 마지막 0.15초만 작은 정착 반응. |
| 카드 받기 | 손이 먼저 도착하고 카드가 손에 붙은 채 이동한 뒤 슬롯에 놓인다. 한 장당 0.45~0.6초. 카드 혼자 날아다니고 팔이 가만히 있지 않게 한다. |
| 기계 처리 | 투입구→레일→출력함으로 카드 위치가 이어진다. 정상은 일정 간격, 위기는 입력 간격만 짧아진다. 정지 직전에 카드 두 장의 앞뒤가 겹치고 벨트가 아래로 처진다. |
| 늑대의 숨 | 0.7초 동안 몸과 주둥이가 뒤로 모이고, 0.9초 동안 앞으로 펴진다. 뒤이어 굽은 바람선과 카드가 이동한다. 반복 호흡 대신 첫째 위기의 큰 숨 한 번, 둘째 위기의 짧은 밀어냄 한 번만 쓴다. |
| 과적과 접힘 | 카드가 닿은 뒤 0.15초 늦게 지붕이 기울고, 접힘선이 안으로 모인다. 전체 집을 제자리에서 흔드는 것으로 대체하지 않는다. |
| 달리기 | 발 한 주기 약 0.34초. 상체는 진행 방향으로 약 8도 기울고, 발 접지에 맞춰 몸이 3~5 단위만 상승한다. 카메라가 따라갈 때 얼굴과 도착 문이 함께 보이게 한다. |
| 공동 선별 | 카드를 펼침→세 형제 동의→생략 표지→상자 이동. 최소 네 단계가 읽히게 한다. 삭제 버튼 한 번으로 늑대를 지우지 않는다. |
| 재배치 | 카드가 원래 위치에서 세 형제의 칸까지 약 0.65초 곡선으로 이동. 각 카드 시작을 0.18초 어긋나게 해 한 번에 쏟아지지 않게 한다. |
| 늑대의 축소 | 생략·분담·휴식 확보의 각 결과 뒤에 카드 덩어리가 분리된다. 단순 투명도 감소만으로 퇴장시키지 않는다. 끝의 작은 실루엣은 한 장의 사각 카드로 접힌다. |

### 7.2 속도·카메라·전환

- 접근·정착은 `easeOutCubic`, 두 위치 사이의 이동은 `smoothstep`을 기본으로 한다. 카드의 마지막 정착에만 최대 4%의 한 차례 오버슈트를 허용한다. 전편에 탄성을 일괄 적용하지 않는다.
- 팬은 1.0~1.4초에 기본 이동을 마친다. 40~43초, 50~53초의 피신은 인물과 함께 더 길게 따라간다. 대사를 읽는 동안 계속 줌하지 않는다.
- 카메라 줌은 기본 대비 약 0.8~1.25배. 첫 전경과 마지막 전경은 별도로 더 넓은 구도를 사용하되, 그때는 중요한 소품 글자를 읽게 하지 않는다.
- 첫째의 종이 넘김→둘째의 투입 카드, 둘째의 레일→셋째의 일정판 선처럼 동일 도형의 위치와 방향으로 장면을 연결한다. 장면마다 검정 페이드나 새 제목판으로 끊지 않는다.
- 위기에서도 화면 전체 흔들림·섬광·빠른 색 반전은 없다. 정지 상태는 정지해 두고, 움직여야 할 물체만 움직인다.
- 마지막 3초는 메시지와 얼굴을 완전히 정지한다. 카메라 이동이나 떠다니는 장식으로 읽기를 방해하지 않는다.

## 8. 구현 계약

### 8.1 단일 파일·오프라인

- 다음 단계 결과물은 `index.html` 한 파일. CSS는 `<style>`, JS는 일반 `<script>`, 그림은 문서 안의 `<svg>`에 둔다.
- 외부 이미지·외부 SVG·래스터 이미지·외부 글꼴·라이브러리·CDN·네트워크 요청·음성·음악·효과음 모두 없음. `fetch`, 원격 링크 로딩, 모듈 import, 빌드 과정에 의존하지 않는다.
- `file://`로 직접 열어 재생 가능해야 한다. 인라인 SVG의 `<defs>`와 내부 참조 `<use href="#...">`는 가능하다. 텍스트를 그림 파일이나 비트맵으로 바꾸지 않는다.
- 그림은 직접 작성한 기본 도형과 path를 조합한다. 작업 폴더 밖의 자료나 파일은 사용하지 않는다.
- 모든 참조 ID는 유일하게 정의한다. 스크립트는 DOM 뒤에서 실행하고 엄격 모드를 사용한다. 전역 변수 노출과 재생마다 이벤트 재등록을 피한다.

### 8.2 단 하나의 시간

- 길이 상수는 `DURATION = 84`초. 장면·자막·모션의 기준 시간이 서로 달라지지 않게 한다.
- 실행 중 시간은 `저장된 재생시간 + (performance.now() - 실행 기준시각) / 1000`으로 구한다. `0~84` 범위로 제한한다.
- `requestAnimationFrame`은 그리기 예약에만 쓴다. 프레임별 `dt` 누적, `t += 1/60`, `setInterval`로 길이를 결정하지 않는다. 느린 프레임이 와도 실제 재생시간에 맞는 상태를 그린다.
- `render(t, reducedMotion)`은 **이전 프레임을 거치지 않아도 해당 시각의 전체 상태를 만들 수 있어야 한다.** 카메라·인물 위치·팔·발·표정·카드 개수와 위치·집 접힘·기계·늑대·완료 표시·자막을 모두 시간에서 도출한다.
- 과거에 쌓인 transform, 증분 회전, 실행 순서에 따라 생기는 DOM 추가·삭제를 사용하지 않는다. 필요한 도형은 초기화 때 만들고 참조를 보관한다.
- 카드 궤적의 차이는 고정 배열로 정한다. 프레임마다 `Math.random()`을 사용하지 않는다. 탐색과 다시 보기의 같은 시각이 같은 그림이어야 한다.
- 집 이동·몸 회전·팔 동작은 중첩 `<g>`로 나눠 서로의 transform을 덮어쓰지 않는다. SVG 속성에 직접 transform을 계산하면 브라우저별 `transform-origin` 차이를 줄일 수 있다.
- 이야기 속 모든 애니메이션은 이 시간에 종속시킨다. 별도 CSS 무한 루프와 JS 타이머를 섞지 않는다. CSS는 버튼 상태·포커스 등 UI에만 사용해도 된다.

### 8.3 재생 상태와 조작

| 상태 | 화면과 조작 |
|---|---|
| 시작 전 | 정지 표지, **재생** 버튼, `00:00 / 01:24`. 탐색은 비활성. |
| 재생 중 | 버튼은 **일시정지**. 현재 시간과 탐색 막대가 갱신됨. |
| 일시정지 | 버튼은 **계속 보기**. 모든 인물·카드·카메라·시계가 같은 순간에 정지함. |
| 종료 | `t=84`의 마지막 화면 유지, 버튼은 **다시 보기**. 프레임 예약 중지. |

- 기본 재생 버튼 하나의 문구와 동작을 상태에 따라 바꾼다. ‘다시 보기’는 누르면 `t=0`부터 즉시 재생하며 표지를 다시 누르게 하지 않는다.
- 다시 보기 전에 기존 RAF를 취소한다. 중복 RAF·숨은 타이머·추가 이벤트 리스너가 생기지 않아야 한다.
- 탐색은 네이티브 `input type="range"`, `min=0`, `max=84`, `step=0.1`. 입력 즉시 해당 시각의 그림·자막·시간을 갱신한다.
- 탐색 시작 전 재생 중이었는지 기억하고 드래그 중에는 멈춘다. 완료 시 이전에 재생 중이고 새 위치가 84 미만이면 재개한다. 일시정지 중 탐색했다면 멈춘 상태를 유지한다. 키보드 탐색에도 같은 원칙을 적용한다.
- 종료 상태에서 84 미만으로 탐색하면 해당 시각의 일시정지 상태가 되고 버튼은 ‘계속 보기’. 84초로 탐색하면 종료 상태다.
- 탭이 숨겨질 때 현재 시간을 확정하고 일시정지한다. 복귀 후 자동 재생하지 않는다.
- `Space`는 입력 요소·버튼·링크에 포커스가 없을 때 재생 상태를 전환한다. 버튼의 네이티브 Space/Enter와 충돌해 두 번 동작하지 않게 한다. 탐색 막대의 방향키 동작을 가로채지 않는다.
- 종료 시 사용자가 다른 컨트롤을 조작하고 있으면 포커스를 강제로 이동하지 않는다. 다시 보기 버튼의 상태 변경은 접근성 상태 메시지로 알린다.

### 8.4 반응형

- 재생기 기본 최대 너비 1120px, 좌우 여백 16px. 좁은 화면에서는 여백 12px. 무대 너비는 컨테이너의 100%, 높이는 `aspect-ratio:16/9`로 정한다.
- 충분한 높이의 데스크톱에서는 자막·조작부 공간 약 190px를 빼고 남는 높이에 맞춰 영상 너비를 줄일 수 있다. 짧은 가로 화면에서는 너비 중심으로 배치하고 페이지 세로 스크롤을 허용한다.
- `body { overflow:hidden }`으로 조작부를 화면 밖에 가두지 않는다. 높이를 억지로 줄여 터치 영역과 자막을 작게 만들지 않는다.
- 자막과 조작부는 SVG 확대·축소의 영향을 받지 않는 HTML이다. 320px 화면에서도 자막 17px 이상, 버튼 높이·터치 영역 44px 이상을 유지한다.
- 데스크톱 조작부는 버튼 / 탐색 / 시간 순서. 600px 미만은 첫 줄 버튼과 시간, 둘째 줄 탐색으로 배치한다. 고정 너비 장면명이 탐색 폭을 빼앗지 않게 한다.
- SVG는 `meet`로 전체를 보존한다. 어떤 화면에서도 `slice`, `object-fit:cover`, 무대 자체의 비균등 확대를 사용하지 않는다.
- 자막 확대·200% 브라우저 줌에서도 가로 스크롤·문장 잘림·버튼 겹침이 없어야 한다. 늘어난 높이는 세로 스크롤로 수용한다.

### 8.5 접근성과 움직임 줄이기

- 문서 `lang="ko"`, 의미 있는 제목, SVG `<title>`·`<desc>`, 이름 있는 재생 제어 영역을 제공한다. 장식 도형은 보조기기에 중복 낭독되지 않게 한다.
- 모든 버튼과 탐색에 명확한 한국어 접근성 이름, 3px 이상의 뚜렷한 `:focus-visible` 외곽선을 둔다. 색만으로 재생·정지·형제를 구분하지 않는다.
- 자막을 `aria-live="polite"`, `aria-atomic="true"`로 제공하되 **문장이 바뀔 때만** DOM 텍스트를 교체한다. 매 프레임 같은 문장을 다시 쓰지 않는다. 시간 표시는 라이브 영역이 아니다.
- 탐색의 `aria-valuetext`에는 현재 위치와 전체 길이를 사람이 읽을 수 있게 넣는다. 숨겨진 표지 컨트롤이 탭 순서에 남지 않게 한다.
- 재생기 아래 네이티브 `<details>`의 **이야기 글로 읽기**를 제공한다. 동일 자막 배열의 문장들을 순서대로 담아 시간제 낭독을 따라가기 어려운 사용자도 읽을 수 있게 한다. 기본은 접힘이다.
- `prefers-reduced-motion: reduce`에서는 이동·달리기·탄성·흔들림·연속 팬·줌을 제거한다. 84초의 시간표와 사건·자막은 유지한다.
- 감소 모드의 화면은 장면별 핵심 구도로 바로 전환한다. 이동하는 카메라만 끄고 인물을 화면 밖에 남기는 방식은 안 된다. 펼쳐진 집, 쌓인 카드, 접힌 집, 이동 후 도착한 형제, 정리된 일정판을 사건 시점에 완성 상태로 보여 준다. 필요하면 최대 0.15초의 불투명도 전환만 쓴다.
- 실행 중 OS 설정이 바뀌어도 다음 렌더부터 대응한다. 기본 모드로 돌아와도 시간·재생 상태를 초기화하지 않는다.

### 8.6 성능과 오류 예방

캐릭터·카드·늑대 부품 등 반복 요소는 재사용하되, 서로 다른 관절을 움직여야 하는 부분은 분리한다. 종이바람은 고정된 18장 이내로 충분하다. 과적량은 추가 더미 실루엣으로 표현하고 수백 개의 DOM을 만들지 않는다. 거대한 blur·displacement 필터는 쓰지 않는다.

매 프레임 DOM 검색·문자열 SVG 재생성·레이아웃 측정은 하지 않는다. 참조를 캐시하고 필요한 속성만 갱신한다. 자막·버튼 문구는 상태가 바뀔 때만 쓴다. 종료·일시정지·숨은 탭에서는 RAF를 남기지 않는다.

## 10. 다음 단계의 제작 순서

1. 단일 HTML 안에 무대·자막·재생기를 만들고, 절대시간 기반 `render(t)`와 상태 전이를 먼저 연결한다.
2. 세 형제·세 준비방·카드·늑대를 새 인라인 SVG로 그린다. 표지, 38초 위기, 67초 해결, 82초 결말의 정지 구도부터 읽히게 만든다.
3. 9장면의 카메라 위치와 인물 위치를 고정하고, 피신 동선을 끝까지 연결한다. 이때 53초에 세 형제가 겹치지 않는지 먼저 확인한다.
4. 펼치기·과적·막힘·선별·분담·휴식 확보의 사건 동작을 넣는다. 자막 큐를 연결하고 84초 연속 재생을 확인한다.
5. 반응형·키보드·움직임 감소·다시 보기를 점검한다. 아래의 스크린숏 검수로 넘어간다.

설계서 단계에서는 이 순서를 실행하지 않는다. 다음 구현 단계에서도 새로운 의존성이나 별도 이미지 파일이 필요 없는 방식을 유지한다.

## 11. 3단계 스크린숏 검토와 4단계 수정 기준

스크린숏은 정해진 시각에 탐색한 뒤 일시정지해 확인한다. 스크린숏만으로 모션과 재생 정확성을 입증할 수 없으므로, 연속 재생과 동작 전후 비교를 함께 수행한다. 아래 항목은 **예정된 검수**이며 현재 통과한 것으로 표시하지 않는다.

### 11.1 대표 시각과 화면

| 시각 | 확인할 화면 | 실패 판정 |
|---|---|---|
| 시작 전 | 제목·늑대·세 형제·재생 버튼 | 제목 잘림, 버튼 찾기 어려움, 클릭 전 재생 |

| 22.5초 | 둘째 기계의 투입·처리·대기 | 입력과 출력 구별 불가, 기계가 처음부터 고장난 듯 보임 |
| 30.5초 | 셋째의 ‘쉼’ 칸과 벤치 | 빈칸이 작은 장식처럼 보이거나 글자가 읽히지 않음 |
| 35.5 / 38.5 / 41.5초 | 숨 모으기→과적 접힘→피신 | 원인·결과 순서 반대, 늑대 미식별, 도착 방향 불명확 |
| 45 / 48.5 / 51.5초 | 처리→막힘→두 형제 이동 | 지붕 접힘과 같은 실패를 반복함, 형제 중첩·누락 |

| 항목 | 자가 검토 질문 | 부족할 때 수정 |

## 13. 예상 위험과 수정 우선순위

가장 큰 위험은 ‘마감 늑대’가 추상적인 종이 폭풍으로만 보이는 것이다. 귀·주둥이·눈의 실루엣을 먼저 확보하고, **입김→카드 이동→과적**의 동작을 또렷하게 한다. 둘째 위험은 빈칸이 일을 더 넣을 공간처럼 보이는 것이다. ‘쉼’ 표지, 벤치, 형제들이 함께 지키는 칸으로 의미를 고정한다. 세 번째 위험은 후반의 카드 정리가 설명 그림으로 끝나는 것이다. 선별하는 손·동의하는 얼굴·실제 카드 이동·기계 재가동·앉는 동작까지 연결한다.

수정 우선순위는 **재생 오류와 화면 잘림 → 사건의 인과와 인물 겹침 → 자막 가독성 → 동작의 무게와 정착 → 장식**이다. 새로운 장면이나 부가 기능을 늘리기보다, 이 설계의 사건이 읽히는지 확인하고 필요한 부분만 고친다.
